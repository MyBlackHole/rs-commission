# 部署与资金操作手册

## 发布前

本项目已从首版未编译源码迁移为 Rust 工作区；每次验收必须对应具体提交和 CI。查看 [验证记录](VERIFICATION.md)，不要把编译通过等同于生产安全验收。禁止首次联调即使用真实资金。

Cargo.lock 已提交，CI 使用 --locked。生产仍需固定 Rust 工具链、镜像 digest 与 CI action commit，完成依赖安全和许可证检查。业务必须确认计佣基数、固定费用是否退回、舍入顺序、冻结起点、退款窗口、税费和欠款处置。默认口径不是已经确认的商业合同。

## 服务与平台

后端 `commissiond` 只提供 API。Web 通过 Dioxus 开发代理或 Nginx 同源代理调用 `/api/v1`；桌面/移动通过 Rust SDK 访问 HTTPS API。部署方法见 README 和 [跨平台说明](CROSS_PLATFORM.md)。

开发 Compose 的 API 地址为 `http://127.0.0.1:8081`；启用 `--profile web` 后，中文前端入口为 `http://127.0.0.1:8080`。不使用 Docker 时，需显式设置 `DATABASE_URL`，并以 `BIND_ADDR=127.0.0.1:8081` 启动后端，与开发代理一致。程序不会自动读取 .env。

移动设备上的 localhost 是设备自身。手机必须连接可访问、证书可信的 HTTPS 服务；不要禁用证书验证。桌面编译检查不等于安装包、系统 WebView 和真实交互已验收；移动端入口配置也不等于 APK/IPA 已生成。

## 数据库与部署

迁移与运行账号分离。运行账号不得为超级用户或表所有者；参考 deploy/runtime-role.sql 并进一步收紧权限。服务器不自动执行 DDL。生产数据库通过可信 TLS 连接（如 sslmode=verify-full），不对公网暴露。迁移先在恢复副本演练。

触发器不防 DB 超级用户；运行角色仍需要钱包更新权限以执行投影。因此不可变账本不等于对任意 SQL 攻击的防篡改存储。

生产 Web 必须在受信反向代理后提供 HTTPS，并设置请求速率、连接数、超时和安全告警。当前没有完整 API 网关限流、MFA、SSO、Prometheus 或高可用部署。Nginx 样例不负责自动签发或续期 TLS 证书。

## 访问凭据

初始化后生成第二个管理员并安全分持，避免所有管理员过期失联。默认初始令牌 90 天，后续签发可设 1..365 天。运营、财务、集成、成员使用独立凭据，不要多人共用管理员。

bootstrap 仅在没有任何凭据时执行；没有公开找回后门。全部管理员遗失或过期需受控 DBA 恢复流程并保存独立审计，不是直接改账。新令牌可通过 `commissiond generate-token` 生成，不需要数据库连接。

令牌只存当前运行内存，刷新或重启后需重新输入；不要放入 URL、截图、工单或仓库。bootstrap 输出包含秘密，勿自动采集进公共日志。双人控制只实现凭据级分离，实际自然人分离依赖组织管理。

## 外部资金事实

capture/refund 是可信业务事实入口，不是匿名支付回调。正式渠道适配器须完成验签、交易状态查询、金额币种校验、订单关联、重放控制与独立对账。

本系统不收款、不退款、不出款；人工核验成功只是财务人员登记外部事实，不能证明银行实际转账。收款方引用也未自动核验。

未来自动出款必须使用稳定提现 UUID 作为渠道业务键。超时查询原交易，不得换号重付。未知结果需持续核查，明确成功或失败后再终结。

## 日常运行

关注 503 重试、锁等待、到期未解冻、负可用余额、长时间执行中/未知提现、Outbox 积压。项目有总览与 JSON 日志，但监控告警、死信和自动归档需另行建设。

内部对账采用一致性快照，wallet_differences 最多返回 100 个差异样本。出现差异先暂停出款、保留证据，设计可审计的修复，不能覆盖历史分录对平。

即使内部 ok=true，仍需核对支付机构与银行账单；当前没有账单导入。平衡账本也可能来自虚假上游支付事实。

## 欠款

负可用余额表示退款发生时资金已被占用或已出款。后续收入解冻会抵扣欠款。未执行提现可驳回释放占用后重新申请；执行中和未知状态不能直接驳回。

当前没有线下追偿收款专用入账。不可通过虚构订单或 UPDATE wallets 补余额。后续应实现带唯一收款业务号、核验证据和独立审核的专用分录流程。

## 重试与故障恢复

响应丢失不等于失败。上游应持久保存业务号、原请求和幂等键；用原键重试或查询状态。跨凭据重试不会取得旧作用域的响应，只由业务号唯一性防止重复效果。

Rust 操作台遇到网络/5xx 不确定性后锁定原参数并复用原键。关闭、刷新或退出会失去临时上下文，必须先保存键与核查记录。内存不是可靠业务队列。本轮未实现跨重启写请求恢复。

提交前崩溃事务回滚；提交后通过幂等和业务号查询恢复。Outbox 消费者须处理已消费、未 ACK 的重复投递。

## 备份、性能与界面限制

备份并演练恢复 PostgreSQL 全部业务数据，不能只备份钱包。制定 PITR、保留与凭据分离策略。

当前没有分区、在线归档、容量压测或 SLO。汇总和内部对账会扫描数据；所有入账触及平台/清算钱包，存在平台级热点。Rust 不自动消除数据库行锁瓶颈，必须真实压测后再考虑分片账本或批量聚合。

Rust 前端当前提供分页列表、服务器试算与共享类型校验的 JSON 操作台。专用业务表单、远程账户搜索、复杂筛选和详情流程尚待完善，不宣称与旧 JS 页面逐项等价。Python/Playwright 仅用于 CI 浏览器测试，不参与前端或后端运行。
